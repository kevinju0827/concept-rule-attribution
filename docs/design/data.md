# 資料

離線紀錄如何產生、分割、儲存與檢查。環境本身的規則寫在 [environment.md](environment.md)。

## 原則

- 第一到第四階段只使用離線紀錄，不訓練策略。
- 世界模型只看得到畫面與動作。標準答案、反事實分支與事件標記只供讀取器訓練、評估與規則判定使用。
- 資料由產生器的程式碼版本與亂數種子完全決定，重新產生必須得到逐位元組相同的內容。

## 行為策略

預設為均勻隨機：每一步從五個動作中以相同機率抽取，與狀態無關。什麼都不做因此在每種情境下都以五分之一的機率出現，模型能在各種情境下看到它的結果。

若覆蓋率檢查未通過，先在 [environment.md](environment.md) 的參數範圍內調整環境；仍不足時，改用混合策略：每一步以機率 ρ 執行事先寫好的行為，例如走向最近的箱子並推動或擊中、走向充電格，其餘時候均勻隨機。混合策略必須滿足兩個條件：

- **每個動作在每個狀態下的機率都至少為 (1−ρ)/5。** 任何情境下都看得到所有動作的結果，包括什麼都不做。
- **只依據畫面上看得到的狀態決定動作，不讀取任何隱藏變數。** 否則動作序列本身會透露隱藏變數，模型可能從「代理做了什麼」而不是從「看到了什麼」推得隱藏變數，讀取結果會被高估。

每一步都記錄所選動作在行為策略下的機率。

## 覆蓋率檢查

規則抽取需要每條規則在訓練資料中出現足夠多次，讀取器需要每個隱藏變數的每個值都出現足夠多次。在產生正式資料之前，先以試驗資料產生覆蓋率報告：

- [environment.md](environment.md) 規則表中每條規則觸發的次數，A6、A7、A8 依不成立的條件組合分開計算。
- 能量、冷卻、耐久度、行進方向每個值出現的次數，以及可識別的比例。
- 預防事件與促成事件的次數。
- 記憶年齡的分布。
- 每一格出現每一種物體種類的次數。逐格的讀取器在某一格從沒見過某種物體時無法輸出它，所以每一格的每一種物體都必須在訓練資料中出現。

覆蓋率報告依條件分別產生；機制組合條件中，依訓練變體分別計算。帶雜訊的條件另外計算推動滑脫與球轉向的次數，因為帶機率結果的規則需要足夠多的紀錄才能估計機率。

每項的最低次數在試驗後寫進第零階段的門檻鎖定紀錄。全部達到最低次數，才產生正式資料。

## 條件與分割

資料分成三個條件，每個條件各自訓練一組世界模型。環境變體的定義見 [environment.md](environment.md)。

| 條件 | 訓練資料的變體 | 用途 |
| --- | --- | --- |
| 主要 | `full`；另一套為 `full-nocool` | 第一到第三階段、歸因檢驗、第四階段的分級推廣、規則開關與三方比對 |
| 機制組合 | `boxes-energy`、`boxes-cooldown`、`balls` 各三分之一 | 第四階段的機制組合檢驗 |
| 帶雜訊 | `full-noisy` | 第四階段的帶雜訊檢驗 |

每個條件的分割以產生器的亂數種子範圍區分，回合不跨分割，同一回合的步驟不會同時出現在不同分割中。

| 分割 | 用途 | 起始規模（估計） |
| --- | --- | --- |
| `pilot` | 試驗：基準線量測、門檻設定、超參數與覆蓋率試驗 | 20 萬步 |
| `train` | 世界模型、讀取器與規則搜尋的訓練 | 100 萬步 |
| `val` | 讀取器正則化強度的選擇、提前停止、規則集的描述長度比較 | 10 萬步 |
| `test` | 與訓練分布相同的保留資料，確認性評估 | 10 萬步 |
| `ood/<方向>/<級>` | 主要條件的分級推廣測試，方向與分級見 [evaluation.md](evaluation.md) | 每級 5 萬步 |
| `compose/<變體>` | 機制組合的測試：`boxes-energy-cooldown`、`boxes-balls`、`full` | 每個變體 5 萬步 |

主要條件中，`full` 與 `full-nocool` 各有一套完整的分割，以相同的亂數種子產生初始狀態，兩套只差在冷卻機制。

`train` 的規模在試驗中以 25%、50%、100% 三種大小訓練世界模型，觀察學習曲線後確認。

## 每一步保存的內容

每個回合保存 `episode_len + 1` 張畫面與 `episode_len` 個動作。下表中「全部」指所有分割，「評估」指 `val`、`test` 與 `ood`。

| 欄位 | 內容 | 分割 |
| --- | --- | --- |
| `obs` | 第 t 張畫面，uint8，高×寬×3 | 全部 |
| `action` | 第 t 步的動作，uint8 | 全部 |
| `behavior_prob` | 該動作在行為策略下的機率，float32 | 全部 |
| `state` | 第 t 步的完整 `State`，含隱藏變數 | 全部 |
| `identifiable`、`memory_age` | 每個隱藏變數是否可識別、記憶年齡 | 全部 |
| `events` | 本步觸發的規則編號，以及不成立的條件 | 全部 |
| `cf_next_state` | 五個動作各自的下一步 `State` | 全部 |
| `prevented`、`enabled` | 每顆球是否被代理預防或促成 | 全部 |
| `cf_next_obs_noop` | 什麼都不做分支的下一張畫面 | 評估 |
| `cf_horizon_noop` | 什麼都不做分支之後 H 步的 `State`，之後執行紀錄中的動作 | 評估 |
| `noise` | 本步抽出的雜訊亂數 | 帶雜訊條件的全部分割 |
| `cf_expected_diff` | 期望的標準答案：各變數在實際分支與什麼都不做分支中不同的機率 | 帶雜訊條件的評估分割 |

回合層級另存：回合編號、分割、產生器種子、環境變體與開啟的機制、環境參數、布局編號、顏色設定、行為策略。

反事實分支的結構化狀態很小，所以全部分割都保存；反事實的畫面較大，只在評估分割保存。它用來比較「預測器對什麼都不做的預測」與「什麼都不做時實際的畫面經編碼後的表示」，這是只有模擬器才能做的檢查。

## 儲存格式

HDF5，以 `h5py` 讀寫。理由：可依索引隨機讀取，不必整份載入記憶體；Farama Foundation 的離線資料標準 Minari 採用 HDF5，LeWorldModel 的官方資料也多為 HDF5（PushT 已改用 Lance），日後轉換的成本低。

- 每個分割分成多個檔案，每檔不超過 2 GB。
- 資料集沿時間軸分塊，每塊為一個回合，並壓縮。壓縮方式在產生正式資料前以讀取速度與檔案大小比較後選定。
- 每個檔案的屬性記錄資料格式版本、環境版本、MiniGrid 版本與產生器的提交。
- 每個分割附一份清單，列出每個檔案的 SHA-256 雜湊值。

**容量估計**：64×64×3 的畫面每張 12,288 位元組，100 萬步未壓縮約 12 GB；112×112×3 時約 38 GB。MiniGrid 的畫面以大片純色為主，壓縮率預期很高，實際數字在第零階段量測。

## 讀取介面

- 世界模型的訓練讀取器只提供 `obs`、`action` 與回合邊界，不提供任何其他欄位。這在程式碼層級強制，見 [architecture.md](architecture.md)。
- 評估讀取器提供全部欄位。

## 資料說明書

每份公開釋出的資料集附一份依 Gebru 等（2021）〈Datasheets for Datasets〉格式撰寫的說明書：動機、組成、產生過程、前處理、用途、散布與維護。組成與產生過程的部分，由清單與覆蓋率報告自動產生。
