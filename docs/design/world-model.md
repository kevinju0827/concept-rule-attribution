# 世界模型

把畫面壓縮成表示、並在表示空間中預測下一步的模型。後續所有檢查都在它產生的表示上進行。

## 組成

| 元件 | 輸入 | 輸出 | 程式碼名稱 |
| --- | --- | --- | --- |
| 編碼器 | 一張畫面 `o_t` | 單張畫面表示 `z_t` | `encode` |
| 信念模組 | `z_1 … z_t` 與 `a_1 … a_{t−1}` | 歷史條件表示 `b_t` | `belief` |
| 轉移頭 | `b_t` 與動作 `a_t` | 下一步單張畫面表示的預測 `ẑ_{t+1}` | `transition` |

預測只在表示空間中進行，不還原成畫面。

兩種表示的區分與理由記錄在 [decisions/0007](../decisions/0007-frame-and-history-representations.md)：`z_t` 只看一張畫面，不可能包含隱藏變數；`b_t` 整合了歷史，隱藏變數只可能存在於這裡。`b_t` 不含當前動作，因此可以解讀為「決定動作之前，對目前狀態的理解」，讀取、介入與歸因都定義在它上面。

## 必要條件

### 「什麼都不做」必須是一個數值

動作以數值輸入轉移頭，「什麼都不做」是動作空間中的一個值，與其他動作走相同的輸入路徑。不得以移除、遮蔽或歸零動作輸入來代替。

兩種做法回答的是不同的問題。輸入明確的「什麼都不做」，問的是「如果我什麼都不做，下一步會是什麼」，這是介入，答案與代理平常的行為無關。移除動作輸入，問的是「不知道我做了什麼的情況下，下一步會是什麼」，答案是依代理平常行為加權的平均。後者會隨代理行為的改變而漂移，不是反事實。

### 歷史條件表示不含當前動作，且涵蓋整個回合

`b_t` 只依賴第 t 步以前的畫面與第 t−1 步以前的動作。符合條件的兩種結構：

- 循環式：`b_t = f(b_{t−1}, z_t, a_{t−1})`。
- 因果遮罩的 Transformer：第 k 個位置的輸入為 `z_k` 加上 `a_{k−1}` 的嵌入，取第 t 個位置最後一層的輸出為 `b_t`。

信念模組可用的歷史長度必須不短於回合長度 `episode_len`。本環境的隱藏變數由回合開始以來的完整歷史決定，歷史較短的模型在設計上就無法表示它們。

### 不得發生表示崩塌

表示崩塌指模型把所有輸入都壓成幾乎相同的表示，使預測永遠正確卻沒有學到任何東西。採用的訓練方法必須在設計上防止這件事，並在訓練過程中監看：

- 固定一批驗證畫面，每個訓練週期計算 `z` 的有效秩（Roy 與 Vetterli，2007）與各維度的標準差。
- 有效秩低於試驗中設定的下限時，該次訓練標為崩塌，不用於任何確認性的結果。

### 只從畫面與動作學習

訓練目標只有兩部分：下一步單張畫面表示的預測誤差，以及防止崩塌的約束。不重建畫面，不加入任何以標準答案為目標的輔助損失，也不把歸因估計放進訓練目標，理由見 [attribution.md](attribution.md)。

訓練時對整個回合的每個位置同時計算預測誤差。

## 多步預測

從 `b_t` 出發，以轉移頭預測 `ẑ_{t+1}`，再把它當作下一張畫面的表示餵回信念模組，依序得到 H 步的預測。H 步歸因的兩個分支都以這種方式展開，第一步分別使用實際動作與什麼都不做，之後使用紀錄中的動作。

## 帶雜訊的環境

帶雜訊的變體中，同一個歷史與動作可能有多個下一步。預測器只輸出單一的 `ẑ_{t+1}`，以均方誤差訓練時，它學到的是對所有可能結果的折衷。本專案接受這一點，不改用輸出分布的模型：這正是「數值上夠用、不求精確」的預測，而歸因與規則的評估在帶雜訊時改以期望的標準答案比較，見 [attribution.md](attribution.md)。

## 差異量

神經網路歸因的純量估計：

```
差異量 = ‖ẑ_實際 − ẑ_不作為‖ / m
```

`m` 為訓練資料中相鄰兩步 `z` 之間歐氏距離的中位數，每個模型計算一次。確認性指標只使用估計值的排序，正規化不影響結論。選擇的理由與放棄的選項記錄在 [decisions/0008](../decisions/0008-difference-measure.md)。

## 診斷

以下各項不是由設計保證的，訓練後必須檢查，並與未經訓練的同架構模型比較：

- **預測品質**：以預測的 `ẑ_{t+1}` 在一批參考表示中找出真正的 `z_{t+1}`，計算排名第一的比例與平均倒數排名（Kipf、van der Pol 與 Welling，2020），分別在 1、5、10 步計算。這是不還原畫面的世界模型常用的評估方式。
- **反事實預測的品質**：比較 `ẑ_不作為` 與什麼都不做分支的實際畫面經編碼後的表示之間的誤差，以及實際分支的預測誤差。兩者接近，代表模型在什麼都不做的分支上預測得一樣好。
- **無效動作的歸因**：代理執行了不是什麼都不做的動作，但在標準答案中沒有任何效果時，例如撞牆、推不動、對空格作用，歸因估計應接近零。
- **崩塌指標**：見上文。

「代理實際執行什麼都不做時歸因應為零」不列為診斷：兩個預測的輸入完全相同，差異恆為零，檢查不到任何東西。

## 對外介面

下游的讀取、規則抽取與歸因只透過以下介面使用世界模型：

| 介面 | 說明 |
| --- | --- |
| `encode(obs) → z` | 批次編碼畫面 |
| `belief(z_seq, prev_actions) → b_seq` | 整個回合的歷史條件表示 |
| `transition(b, action) → ẑ` | 一步預測 |
| `rollout(b_t, actions) → ẑ_seq` | 多步預測 |

凍結後的表示依 [architecture.md](architecture.md) 的方式快取，下游不重新執行模型。

## 候選實作

以 LeWorldModel 為起點的提議，記錄在 [decisions/0003](../decisions/0003-lewm-as-world-model-starting-point.md)，狀態為提議中。在它被接受之前，本規格只規定上述條件，不指定實作。

不論採用哪一個起點，都必須符合本文件的條件；若起點的原始設計不符合，例如歷史太短，或動作進入了產生 `b_t` 的每一層，必須修改，而修改後的版本要重新確認訓練穩定。
