# 環境

代理看到什麼、能做什麼、世界依什麼規則變化，以及標準答案從哪裡來。資料如何產生與儲存寫在 [data.md](data.md)。

## 模擬器

MiniGrid，由 Farama Foundation 維護的格子世界套件，以 `pip install minigrid` 安裝並固定版本。本文件中所有已確認的行為，均以 3.1.0 版為準；升級版本後，必須重新執行[環境必須滿足的性質](#環境必須滿足的性質)中的全部檢查。

選擇它而非 Minecraft 或自行從頭撰寫的理由，記錄在 [decisions/0002](../decisions/0002-minigrid-as-environment.md)。客製環境的具體設計與取捨，記錄在 [decisions/0005](../decisions/0005-deterministic-custom-environment.md)。

客製環境以 MiniGrid 官方的自建方式撰寫：繼承 `MiniGridEnv`，實作 `_gen_grid`，並完整改寫 `step`。程式碼中的名稱為 `PushRoomEnv`，以 `CRA/PushRoom-v0` 註冊。

## 觀測

模型的輸入只有畫面，不接觸任何文字或符號。

- 畫面以 `get_frame(highlight=False, tile_size=...)` 繪製，涵蓋整個格子。`RGBImgObsWrapper` 會繪製完整畫面，但它沿用環境的 `highlight` 設定，而這個設定預設開啟，會把代理前方的視野畫成較亮的灰色，使許多格子的外觀隨代理的位置與朝向改變（已從原始碼確認）。因此一律關閉。
- 畫面大小等於格子邊長乘以每格像素數。8×8 格子、每格 8 像素時為 64×64×3（已確認）。
- 若編碼器以固定大小的方塊切分畫面，每格像素數設為方塊邊長，讓每個方塊恰好對應一格。例如方塊邊長 14 像素時，畫面為 112×112×3。最終的每格像素數在第零階段量測顯示記憶體用量後決定。
- 畫面大小在所有資料分割與所有推廣測試中固定，不隨格子內容改變。

## 世界

格子為 8×8，含外圈的牆，內部可活動的區域為 6×6。

| 物體 | MiniGrid 基礎類別 | 畫面上看得到的 | 看不到的 |
| --- | --- | --- | --- |
| 代理 | 內建 | 位置、朝向（紅色三角形） | 能量、推動冷卻 |
| 箱子 | `Box` 的子類別 | 位置、顏色、受擊提示（實心外觀，只持續一張畫面） | 耐久度 |
| 巡邏球 | `Ball` 的子類別 | 位置、顏色 | 行進方向 |
| 充電格 | `Floor` 的子類別 | 位置（綠色地板） | 無 |
| 牆 | `Wall` | 位置（灰色） | 無 |

每個箱子與球都有固定的編號，整個回合不變，用來在標準答案中追蹤它們。

顏色的分配：紅色保留給代理，灰色給牆，綠色給充電格。訓練資料中箱子為黃色、球為藍色；紫色保留給推廣測試。

### 狀態變數

| 變數 | 程式碼名稱 | 歸屬 | 可見性 | 值域 |
| --- | --- | --- | --- | --- |
| 每格的物體種類 | `cell_type` | 環境 | 可見 | 空、牆、箱子、球、充電格 |
| 每格的物體顏色 | `cell_color` | 環境 | 可見 | MiniGrid 的六種顏色 |
| 代理位置 | `agent_pos` | 自身 | 可見 | 內部 36 格 |
| 代理朝向 | `agent_dir` | 自身 | 可見 | 0 至 3 |
| 能量 | `energy` | 自身 | 隱藏 | 0 至 `energy_max` |
| 推動冷卻 | `cooldown` | 自身 | 隱藏 | 0 至 `push_cooldown` |
| 箱子耐久度 | `durability` | 他者 | 隱藏 | 1 至 `box_durability` |
| 受擊提示 | `hit_cue` | 他者 | 可見，只持續一張畫面 | 有或無 |
| 球的行進方向 | `heading` | 他者 | 動態：單張畫面看不到，連續畫面可推得 | 四個方向 |

步數用於截斷回合，不屬於規則所作用的狀態。

### 參數

以下為起始值，依 [data.md](data.md) 中的覆蓋率試驗調整，調整結果寫進門檻鎖定的決策紀錄。

| 參數 | 程式碼名稱 | 起始值 |
| --- | --- | --- |
| 回合長度 | `episode_len` | 64 |
| 箱子數 | `num_boxes` | 每回合從 2、3 中抽取 |
| 球數 | `num_balls` | 每回合從 1、2 中抽取 |
| 充電格數 | `num_chargers` | 1 |
| 能量上限 | `energy_max` | 2 |
| 推動冷卻步數 | `push_cooldown` | 3（時間規則開）或 0（關） |
| 箱子初始耐久度 | `box_durability` | 2 |
| 內部牆面 | `interior_walls` | 每回合從 0 至 2 中抽取，各為一個單獨的格子 |

回合開始時，內部牆面、充電格、箱子、球、代理依序放在隨機的空格上；每顆球隨機取水平或垂直方向巡邏，起始方向隨機。代理的能量為上限，冷卻為零，所有箱子的耐久度為初始值。亂數只在這裡使用。

訓練資料中放入單格的內部牆面，是為了讓每一格都出現過「牆」：逐格的讀取器在某一格從沒見過某種物體時，無法輸出它，推廣測試中的新布局會因此在讀取上必然失敗，而與規則無關。推廣測試改變的是牆面的形狀，例如連成一段或形成走廊，而不是牆能不能出現在某一格。

## 動作空間

| 編號 | 名稱 | 程式碼名稱 |
| --- | --- | --- |
| 0 | 左轉 | `left` |
| 1 | 右轉 | `right` |
| 2 | 前進 | `forward` |
| 3 | 作用 | `toggle` |
| 4 | 什麼都不做 | `noop` |

不包含 MiniGrid 的撿起與放下：本環境沒有可撿起的物體，它們在任何狀態下都等同什麼都不做。

### 什麼都不做的語意

代理不施加任何效果：跳過代理的動作處理，其餘所有環境過程照常進行。它不是「整個世界不變」，球照樣移動、計時器照樣倒數。理由記錄在 [decisions/0006](../decisions/0006-noop-semantics-and-contrastive-attribution.md)。

它必須以一個數值輸入模型，理由見 [world-model.md](world-model.md)。任何修改動作或規則的改動，都必須重新確認這個語意，因為它一旦改變，歸因估計所衡量的東西也會跟著悄悄改變。

MiniGrid 3.1.0 中的相關行為（已確認）：基礎類別的 `done` 不改變任何狀態、但會讓步數加一；`GoToDoorEnv` 與 `GoToObjectEnv` 把 `done` 用來結束回合；`DynamicObstaclesEnv` 把動作空間限制為三種。本環境不沿用這些類別，自行定義上表的動作。

## 規則

這是環境真正的狀態轉移函式，也是規則抽取要找回的對象。每條規則有編號，第三階段以編號回報每條規則是否被正確找回。

每一步依序處理以下五個階段。代理先動，所以代理的動作可以在同一步內擋下或放行一顆球。

**一、提示消退。** 上一步亮起的受擊提示熄滅。

**二、代理的動作。** 以下「前方」指代理朝向的相鄰格，「後方」指箱子在推動方向上的下一格。「空」指沒有任何物體，充電格也不算空。

| 編號 | 動作 | 條件 | 效果 |
| --- | --- | --- | --- |
| A1 | 左轉 | 無 | 朝向逆時針轉一格 |
| A2 | 右轉 | 無 | 朝向順時針轉一格 |
| A3 | 前進 | 前方為空或為充電格 | 代理前進一格 |
| A4 | 前進 | 前方為牆或球 | 無 |
| A5 | 前進 | 前方為箱子，後方為空，能量大於 0，冷卻為 0 | 箱子與代理各前進一格，能量減一，記為推動成功 |
| A6 | 前進 | 前方為箱子，後方不為空 | 無 |
| A7 | 前進 | 前方為箱子，能量為 0 | 無 |
| A8 | 前進 | 前方為箱子，冷卻大於 0 | 無 |
| A9 | 作用 | 前方為箱子，能量大於 0 | 耐久度減一，能量減一，受擊提示亮起；耐久度歸零時箱子消失 |
| A10 | 作用 | 前方不是箱子，或能量為 0 | 無 |
| A11 | 什麼都不做 | 無 | 無 |

A6、A7、A8 可能同時成立；效果都是無，事件標記中記錄所有不成立的條件。A8 是可切換的時間規則：冷卻步數為 0 時，冷卻永遠為 0，A8 永遠不成立。

**三、巡邏球。** 依編號由小到大處理。

| 編號 | 條件 | 效果 |
| --- | --- | --- |
| E1 | 行進方向上的下一格為空，且代理不在該格 | 球前進一格 |
| E2 | 否則 | 行進方向反轉，球留在原地 |

**四、計時器。**

| 編號 | 條件 | 效果 |
| --- | --- | --- |
| E3 | 本步推動成功 | 冷卻設為冷卻步數 |
| E4 | 否則 | 冷卻減一，最低為 0 |

因此推動成功之後的連續 `push_cooldown` 步內，推動都無效。

**五、充電。**

| 編號 | 條件 | 效果 |
| --- | --- | --- |
| E5 | 代理位於充電格上 | 能量設為上限 |

最後步數加一，達到回合長度時截斷回合。回合不會因其他原因提前結束，也沒有獎勵；本專案只使用離線紀錄，不訓練策略。

## 對應原本的必要要素

| 要素 | 本環境中的形式 | 支撐的評估 |
| --- | --- | --- |
| 環境自身的動態 | 巡邏球、冷卻倒數、提示消退 | 區分環境自己的變化與代理造成的變化 |
| 屬於其他物體的隱藏變數 | 箱子耐久度，以一張畫面的受擊提示與最後的碎裂呈現 | 第一階段的他者隱藏變數 |
| 屬於代理自身的隱藏變數 | 能量、推動冷卻 | 第一階段的自身隱藏變數，與他者分開回報 |
| 條件式規則 | A5 至 A8：推動只在後方為空、有能量、不在冷卻時成功 | 第二、三階段的情境切換 |
| 可切換的看不見的時間規則 | A8 與 E3、E4：推動冷卻，以 `push_cooldown` 開關 | 第四階段的成對比較 |
| 預防事件 | 代理或被推的箱子擋住球的下一格 | 歸因中的間接影響 |

以下要素在第四階段之後才需要：規則參數在訓練中途改變，例如冷卻步數，用來檢驗代理追蹤的是變化中的因果關係，還是記住了固定的關係。

## 可識別性

每個隱藏變數都必須有可見的後果，而且它在每一步的值都能由回合開始以來的畫面與動作歷史決定。

| 變數 | 可見的後果 | 如何由歷史決定 |
| --- | --- | --- |
| 能量 | 能量為 0 時推動與作用無效 | 初始為上限；成功的推動與擊中都看得見；站上充電格看得見 |
| 推動冷卻 | 冷卻中推動無效 | 上一次成功推動看得見 |
| 耐久度 | 歸零時箱子消失 | 初始值固定；每次擊中有受擊提示 |
| 行進方向 | 球的移動 | 球移動一次後即確定；被擋時方向反轉，可由當時的佔用情形推得 |

環境在每一步為每個隱藏變數記錄兩個量：

- **是否可識別**：在所有與目前為止的畫面與動作歷史相符的隱藏狀態中，這個變數是否只有一個可能的值。能量、冷卻與耐久度的初始值固定，在完整歷史下永遠可識別；行進方向在回合開始時不可識別，以列舉所有可能的起始方向、保留與觀測相符者的方式計算。
- **記憶年齡**：決定這個值的最近一次可見事件距今幾步，回合開始也算一次事件。

## 標準答案

標準答案直接從環境物件的內部狀態讀取，輸出為一個結構化的 `State`：逐格的物體種類、顏色與物體編號，代理的位置、朝向、能量、冷卻，每個箱子的耐久度與提示，每顆球的行進方向。`State` 的定義是環境、讀取、規則抽取與評估共用的唯一來源。

不經觀測包裝器讀取：隱藏變數依定義不會出現在任何觀測中。

標準答案只用於讀取器的訓練目標、評估與規則的判定，絕不作為世界模型的輸入，也不提供給規則搜尋。

## 反事實標準答案

以 `copy.deepcopy` 複製當下的環境，在各分支執行不同的動作，比較結果的 `State`。本環境的轉移是確定性的，複製後相同動作必然得到相同結果；不同動作之間的差異，就是動作造成的精確影響。

- **一步**：每一步對全部五個動作各算一次下一步的 `State`。其中什麼都不做的分支，是歸因的對照。
- **H 步**：實際動作與什麼都不做兩個分支，之後都執行紀錄中實際發生的動作，比較 H 步內每一步的差異。H 的起始值為 8。
- **預防與促成事件**：某顆球在什麼都不做的分支中前進、在實際分支中被擋下，記為被代理預防；反過來則記為被代理促成。

在 `DynamicObstaclesEnv` 上已確認：複製後執行相同動作，得到完全相同的下一個畫面。但它的障礙物在代理動作之前、以拒絕取樣移動，抽亂數的次數取決於代理的位置，因此不同動作的分支會在之後的步驟中因亂數錯開而產生與因果無關的差異（已從原始碼確認）。本環境不使用隨機動態，避開這個問題。日後若加入隨機動態，每一步必須以固定方式抽出固定數量的亂數，與動作和狀態無關。

## 環境必須滿足的性質

以下性質寫成自動化測試，任何修改環境、規則或 MiniGrid 版本之後都必須全部通過。第零階段的環境驗收以它們為準。

1. **確定性**：相同的 `State` 與動作，得到相同的下一個 `State` 與相同的畫面。
2. **什麼都不做**：執行什麼都不做時，代理的位置、朝向、能量與所有箱子不因代理而改變；結果等於只執行環境的各個階段。
3. **無效的動作等同什麼都不做**：規則 A4、A6、A7、A8、A10 成立時，下一個 `State` 與什麼都不做的分支完全相同。
4. **隱藏變數不影響畫面**：只在能量、冷卻、耐久度、行進方向上不同的兩個 `State`，繪出逐像素相同的畫面。
5. **提示只持續一張畫面**。
6. **時間規則的開關不影響其他規則**：冷卻為 0 的狀態下，開與關兩種設定的轉移，除了推動成功後的冷卻值以外完全相同。
7. **可識別性的計算正確**：在小型案例上與暴力列舉的結果一致。
8. **繪圖快取正確**：同一物體的不同外觀反映在 `encode()` 中。MiniGrid 以物體的編碼、代理朝向、陰影與每格像素數作為格子圖片的快取鍵（已從原始碼確認），外觀不同但編碼相同時會回傳舊圖片。

## 硬體

目標硬體為單張 8 GB 顯示記憶體的 GPU，顯示記憶體是主要限制。

MiniGrid 本身以 CPU 執行、繪圖成本低，顯示記憶體幾乎全部可留給世界模型。
