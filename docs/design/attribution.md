# 歸因

回答「這個變化有多少是我造成的」。本專案以兩種方式估計，並與環境提供的標準答案比對。

## 定義

歸因是相對於「什麼都不做」的對照：某一步的影響，是在相同歷史下，實際動作的結果與什麼都不做的結果之差。「什麼都不做」指代理不施加任何效果，環境照常運作，見 [environment.md](environment.md)。定義的理由、它與「以所有動作的平均為對照」的不同，以及「若非如此」定義的已知盲點，記錄在 [decisions/0006](../decisions/0006-noop-semantics-and-contrastive-attribution.md)。

- **一步歸因**：比較第 t+1 步的結果。這是主要指標。
- **H 步歸因**：兩個分支在第 t 步分別執行實際動作與什麼都不做，之後都執行紀錄中實際發生的動作，比較第 t+1 到 t+H 步的結果。用來檢驗延遲的影響，H 的起始值為 8。

代理實際執行什麼都不做的步驟，兩個分支相同，不納入任何指標。

## 三種估計

### 標準答案

依 [environment.md](environment.md) 的方式複製環境，分別執行實際動作與什麼都不做，兩個分支的 `State` 差異就是標準答案。差異表示為一組（變數，實際分支的值，什麼都不做分支的值）。

### 神經網路歸因

從同一個歷史條件表示出發，以轉移頭產生兩個下一步的預測：

```
ẑ_實際   = transition(b_t, a_t)
ẑ_不作為 = transition(b_t, 什麼都不做)
```

- **純量估計**：兩者的差異量，定義見 [world-model.md](world-model.md)。
- **結構化估計**：以讀取器把兩個預測各自讀成 `State`，比較兩者的差異，形式與標準答案相同。讀取方式見 [readout.md](readout.md)。

H 步時，兩個分支依 [world-model.md](world-model.md) 的多步預測方式展開。

### 規則歸因

以 [rule-extraction.md](rule-extraction.md) 抽出的狀態轉移函式，從同一個讀出的 `State` 出發，分別模擬實際動作與什麼都不做，兩個結果的差異就是規則歸因估計。H 步時重複套用同一個函式，之後的步驟使用紀錄中的動作。

這個估計以明確的狀態表示，例如「這一步讓某個箱子的耐久度減少 1」，可以逐項閱讀與檢查。

另以真實的 `State` 代替讀出的 `State` 計算一次，作為讀取不出錯時的上限。

### 基準

| 基準 | 計算方式 | 用途 |
| --- | --- | --- |
| 未經訓練的模型 | 相同架構、未經訓練的模型的神經網路歸因 | 所有指標都必須勝過它 |
| 觀測變化量 | 相鄰兩步單張畫面表示的距離，以相同的 m 正規化 | 不做反事實、把所有變化都算給代理的估計；它會把環境自己的變化誤算進來 |
| 動作平均對照 | 實際動作的預測與所有動作預測的平均之間的差異量 | 探索性比較，見 [decisions/0006](../decisions/0006-noop-semantics-and-contrastive-attribution.md) |

## 分層

整體的平均會被容易的情況主導。例如轉向在標準答案中永遠有效果，什麼都不做永遠沒有。因此以下列標記把步驟分層，一步可以有多個標記，指標在每一層分別計算：

| 標記 | 定義 |
| --- | --- |
| 直接效果 | 一步的標準答案中，代理或箱子的位置、朝向有差異 |
| 無效動作 | 動作不是什麼都不做，但一步的標準答案沒有任何差異，例如撞牆、推不動、對空格作用 |
| 隱藏效果 | 一步的標準答案中，至少一個隱藏變數有差異 |
| 間接效果 | 至少一顆球被代理預防或促成 |
| 延遲效果 | 一步的標準答案中可見變數沒有差異，但 H 步內某一步有 |

另依動作種類分開計算，避免「看動作就知道答案」的捷徑：例如在所有「前進」的步驟中，區分推動成功與推動失敗。

## 指標

| 編號 | 指標 | 計算方式 |
| --- | --- | --- |
| M1 | 偵測 | 在同一種動作的步驟中，以純量估計區分「一步的標準答案有差異」與「沒有差異」，計算 ROC 曲線下面積與精確率–召回率曲線下面積 |
| M2 | 大小 | 純量估計與標準答案中有差異的變數個數之間的 Spearman 等級相關 |
| M3 | 結構 | 結構化神經網路歸因與規則歸因，相對於標準答案的逐變數精確率、召回率、F1，以及整組差異完全正確的比例 |
| M4 | 間接 | 預防與促成事件的召回率與精確率 |
| M5 | 延遲 | 對 k = 1 到 H，以 k 步的估計計算 M1 與 M3 |

M1 與 M2 只依賴估計值的排序。

## 規則解釋不了的變化

實際觀察到的變化，扣除規則能解釋的部分後的剩餘，**不得直接算作代理造成的**。剩餘部分混合三種來源：

1. 沒有抽完整的動作規則，也就是確實由代理造成、但規則沒涵蓋的部分。
2. 規則沒有涵蓋的其他來源，例如沒被抽到的環境自身動態，或看不見的變數。
3. 規則本身的誤差，包括讀取錯誤。

區分方式是改變自己的動作：在相同情境下改變動作，剩餘部分跟著改變的，才歸為第一種。其餘以「無法歸因」回報，不分配給任何來源。

「在相同情境下改變動作」有兩種做法，分開回報：

- **有特權**：複製環境，在完全相同的情境下執行其他動作，取得畫面後讀成 `State`，計算各動作下的剩餘。這需要代理在真實世界中沒有的能力。
- **沒有特權**：在紀錄中找出讀出的 `State` 在規則條件所用的範圍內相同、但動作不同的其他時間點，比較剩餘。

本環境的規則表已知，所以每一筆剩餘的真正來源都可以標出。以此評估兩種做法的判斷是否正確，並回報兩者的差距，也就是複製環境這項特權帶來的優勢。

在單一代理、環境規則完整的條件下，這三種來源可以分開。日後加入其他行動者時，第二種來源會大幅增加，這項規定在那時最為關鍵。

## 三方比對

每一步記錄神經網路估計（純量與結構化）、規則估計與標準答案。比對方式與通過條件在 [evaluation.md](evaluation.md)。

三者一致，表示兩種估計都抓到了真實的因果；不一致時，與標準答案比對可以指出是哪一種估計出錯。不一致的步驟逐一分類：只有神經網路偏離、只有規則偏離、兩者都偏離。

## 不作為獎勵

兩種歸因估計都不加入訓練目標。以高歸因作為獎勵，會讓代理傾向盡量影響世界，這和準確估計自己的影響是不同的目標。
