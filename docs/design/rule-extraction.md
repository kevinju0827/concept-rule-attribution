# 規則抽取

從表示空間抽出精確、可驗證的規則，過程中不使用大型語言模型。

## 流程

1. **讀成狀態。** 依 [readout.md](readout.md) 把每一步的表示讀成 `State`。讀取錯誤會直接變成規則錯誤，所以每次抽取都一併記錄各目標的讀取準確率。
2. **建立特徵。** 從讀出的 `State` 序列算出規則條件可以使用的命題，見下文。
3. **搜尋規則。** 先從「什麼都不做」的轉移抽出環境規則，再在固定環境規則的前提下，為每個動作抽出動作規則。
4. **以回放篩選。** 把候選規則套用到 `train` 分割的讀出狀態上，保留重現比例達到 q 的規則。
5. **以真實狀態判定。** 在保留資料上，把抽出的狀態轉移函式套用到真實狀態，判定每條規則是否正確。
6. **端到端量測。** 在保留資料上，把同一個函式套用到讀出的狀態，量測能精確重現的比例。

步驟 4 與 5 的分工記錄在 [decisions/0012](../decisions/0012-noise-tolerant-rule-search.md)：搜尋時容忍讀取誤差，正確與否以真實狀態判定。搜尋過程不接觸任何真實狀態。

## 特徵

規則的條件由以下命題組成，全部以代理或物體自身為參考點：

- 代理前方一格、前方第二格的物體種類。
- 能量是否為 0、冷卻是否大於 0、前方箱子的耐久度是否為 1。
- 每顆球行進方向上的下一格的物體種類，以及代理是否在該格。
- 代理是否位於充電格上。
- 由讀出的狀態序列推得的歷史特徵：距離上一次觀察到成功推動的步數、距離上一次站上充電格的步數。

歷史特徵是退路：若某個隱藏變數無法從表示中讀出，時間規則仍可能以歷史特徵的形式被找回。最後的報告說明每條規則是以哪一種特徵表達的。

## 規則形式

每條規則是「條件 → 效果」：條件是上述命題的合取，例如「前方是箱子 且 前方第二格是空 且 能量不為 0」；效果是對 `State` 的一組具型別的修改：

| 效果 | 例子 |
| --- | --- |
| 移動物體 | 代理往前一格；箱子往前一格 |
| 轉向 | 代理朝向順時針一格；球的行進方向反轉 |
| 設定變數 | 冷卻設為 3；能量設為上限 |
| 增減變數 | 能量減一；耐久度減一 |
| 移除物體 | 箱子消失 |
| 提示 | 某格的受擊提示亮起 |

所有規則合起來輸出為一個可執行的 Python 模組，包含 `agent_phase(state, action)`、`env_phase(state)` 與 `step(state, action)`，輸入與輸出都是與環境共用的 `State`。每條規則以註解標出它涵蓋的訓練紀錄數與重現比例。這個模組本身就是抽取的成果，可以直接閱讀、執行與修改；它不得引用環境真正的轉移程式碼，這在程式碼層級強制，見 [architecture.md](architecture.md)。

`step` 的結構不預設：「先代理、後環境」與「先環境、後代理」兩種組合方式都嘗試，以訓練資料上的重現程度選擇。

## 兩類規則

- **環境規則**：從「什麼都不做」的轉移中抽取。在這些轉移中代理不施加任何效果，所有變化都來自環境。
- **動作規則**：固定環境規則後，對每個動作搜尋代理階段的修改，使組合後的結果重現實際的轉移。

分開抽取，是為了讓 [attribution.md](attribution.md) 中的規則歸因估計可以成立：用同一個函式分別模擬實際動作與「什麼都不做」，兩者的差就是代理自身的影響。

## 搜尋方法

不使用大型語言模型。候選方法：

1. **列舉合取條件。** 對每個（動作，效果種類），列舉最多 k 個命題的合取，取與資料相符的最一般條件。這與物件導向馬可夫決策過程的條件效果學習相同（Diuk、Cohen 與 Littman，2008）。
2. **決策樹。** 對每個（動作，狀態變數的變化）以命題為特徵訓練深度有限的決策樹，把每個葉節點轉成一條規則。
3. **歸納邏輯程式設計**，例如 Popper（Cropper 與 Morel，2021）。只在前兩種無法表達涉及隱藏變數的規則時才使用。

在第三階段開始前，以[上限對照](#上限對照)比較候選方法：在真實狀態上，哪一種能找回環境規則表中最多的規則、執行時間多長、規則多簡潔。選定的方法與 k 值寫進第三階段的門檻鎖定紀錄。

## 接受與判定

- **篩選**：在讀出的狀態上，候選規則重現它所涵蓋的訓練紀錄中至少比例 q 的部分才保留。q 依試驗中量得的讀取準確率設定。
- **判定**：在保留資料的真實狀態上，一條規則只有在精確重現它涵蓋的每一筆轉移時才算正確，不接受「大致吻合」。兩個函式只要在所有保留資料上的輸出相同就視為相同，不比較程式碼的文字。
- **無法解釋的轉移**：無法被任何已接受規則解釋的轉移，以比例回報，不得省略。

## 回報的內容

- 對 [environment.md](environment.md) 規則表中的每條規則（A1 至 A11、E1 至 E5）：在保留資料中該規則適用的轉移上，抽出的函式是否全部重現正確。
- 保留資料上，下一步 `State` 完全正確的比例：套用到真實狀態一次，套用到讀出狀態一次。
- 各讀取目標的準確率。
- 函式的規模：規則數、每條規則的命題數。

## 上限對照

把相同的搜尋流程直接套用在真實狀態上，不經過表示空間，q 為 1。這個結果代表搜尋方法本身能做到的上限。實際結果與上限之間的差距，就是經過表示空間所造成的損失，用來判斷失敗出在表示空間還是出在搜尋方法。

上限對照只需要環境與資料，在第零階段的環境驗收後即可進行，與第一階段並行。

## 規則開關的比較

在時間規則開與關的兩套資料上分別抽取。理想的結果是：兩個函式的差別恰好是冷卻相關的規則（A8、E3、E4），其餘完全相同。
