# 規則抽取

從表示空間抽出精確、可驗證的規則，過程中不使用大型語言模型。

## 流程

1. **從表示讀出狀態。** 使用第一階段通過檢查的線性讀取器，把表示轉成明確的狀態：物體、位置、屬性。線性讀取器指只做加權相加的最簡單讀取方式，能讀出代表資訊以規整的方式存在於表示中。
2. **搜尋規則。** 在讀出的狀態序列上，搜尋能解釋每一步狀態變化的規則。
3. **以回放驗證。** 把候選規則套用到實際紀錄上，只保留能精確重現紀錄的規則。
4. **在保留資料上檢驗。** 以沒有用於搜尋的紀錄，量測規則能精確重現的比例。

讀取錯誤會直接變成規則錯誤，所以每次抽取都要一併記錄第一步的讀取準確率。

## 規則形式

每條規則是「條件 → 效果」：條件是狀態上的判斷，例如「代理前方的格子是空的」；效果是狀態的變化，例如「代理的位置往前一格」。

所有規則合起來輸出為一個可執行的 Python 狀態轉移函式：輸入目前狀態與動作，輸出下一個狀態。這個函式本身就是抽取的成果，可以直接閱讀、執行與修改。

## 兩類規則

- **環境自身的規則**：從「什麼都不做」時的狀態轉移中抽取，描述不受代理影響的變化。
- **動作規則**：描述每個動作如何改變狀態。

分開抽取，是為了讓 [attribution.md](attribution.md) 中的規則歸因估計可以成立：用同一個函式分別模擬實際動作與「什麼都不做」，兩者的差就是代理自身的影響。

## 搜尋方法

不使用大型語言模型。候選方法包括列舉條件與效果的組合，以及決策樹這類可直接閱讀的模型。尚未決定，在第三階段開始前以小規模試驗比較後再決定。

## 接受標準

一條規則只有在能精確重現它所涵蓋的每一筆紀錄時才被接受，不接受「大致吻合」。無法被任何已接受規則解釋的狀態轉移，以比例回報，不得省略。

## 上限對照

把相同的搜尋流程直接套用在環境提供的真實狀態上，不經過表示空間。這個結果代表搜尋方法本身能做到的上限。實際結果與上限之間的差距，就是經過表示空間所造成的損失，用來判斷失敗出在表示空間還是出在搜尋方法。
