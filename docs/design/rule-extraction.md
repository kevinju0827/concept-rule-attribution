# 規則抽取

從表示空間抽出結構正確、可驗證、可組合的規則，過程中不使用大型語言模型。

本專案中的「精確」指結構：條件與效果的組成是否正確。數值上的準確度不是必要條件，以保真度連續量測。區分這兩者的理由記錄在 [decisions/0014](../decisions/0014-structural-correctness-and-mdl-rule-selection.md)。

## 流程

1. **讀成狀態。** 依 [readout.md](readout.md) 把每一步的表示讀成 `State`。讀取錯誤會直接變成規則錯誤，所以每次抽取都一併記錄各目標的讀取準確率。
2. **建立特徵。** 從讀出的 `State` 序列算出規則條件可以使用的命題，見下文。
3. **搜尋候選規則。** 先從「什麼都不做」的轉移抽出環境規則，再在固定環境規則的前提下，為每個動作抽出動作規則。
4. **以描述長度選擇規則集。** 在 `val` 分割的讀出狀態上，選出描述長度最短的規則集。
5. **以真實狀態判定。** 在保留資料上，把選出的狀態轉移函式套用到真實狀態，判定每條真實規則的結構是否被找回，並量測保真度。
6. **端到端量測。** 在保留資料上，把同一個函式套用到讀出的狀態，量測保真度。

步驟 3 與 4 只使用讀出的狀態，不接觸任何真實狀態；真實狀態只用於步驟 5 的判定。

## 特徵

規則的條件由以下命題組成，全部以代理或物體自身為參考點：

- 代理前方一格、前方第二格的物體種類。
- 能量是否為 0、冷卻是否大於 0、前方箱子的耐久度是否為 1。
- 每顆球行進方向上的下一格的物體種類，以及代理是否在該格。
- 代理是否位於充電格上。
- 由讀出的狀態序列推得的歷史特徵：距離上一次觀察到成功推動的步數、距離上一次站上充電格的步數。

歷史特徵是退路：若某個隱藏變數無法從表示中讀出，時間規則仍可能以歷史特徵的形式被找回。最後的報告說明每條規則是以哪一種特徵表達的。

## 規則形式

每條規則是「條件 → 效果」：條件是上述命題的合取，例如「前方是箱子 且 前方第二格是空 且 能量不為 0」；效果是對 `State` 的一組具型別的修改：

| 效果 | 例子 |
| --- | --- |
| 移動物體 | 代理往前一格；箱子往前一格 |
| 轉向 | 代理朝向順時針一格；球的行進方向反轉 |
| 設定變數 | 冷卻設為 3；能量設為上限 |
| 增減變數 | 能量減一；耐久度減一 |
| 移除物體 | 箱子消失 |
| 提示 | 某格的受擊提示亮起 |

兩種擴充：

- **帶例外的規則**：規則在它涵蓋的紀錄中有一部分不成立。例外的比例明確記錄在規則旁，不隱藏。
- **帶機率結果的規則**：同一條件下有多個可能的效果，各附機率，例如「推動條件成立 → 0.9 的機率前進，0.1 的機率沒有效果」。用於帶雜訊的環境，形式與 Pasula、Zettlemoyer 與 Kaelbling（2007）的機率關係規則相同。

**缺席的變數。** 某個環境變體沒有某個變數時（例如沒有能量機制），以它為對象的命題視為成立，以它為對象的效果不適用。這是規則語言對多個機制如何組合所做的假設：同一個互動的前提條件取合取，效果取聯集。本專案的環境依這個方式建構，見 [environment.md](environment.md)；在組合方式不同的環境中，這個假設不成立。

所有規則合起來輸出為一個可執行的 Python 模組，包含 `agent_phase(state, action)`、`env_phase(state)` 與 `step(state, action)`，輸入與輸出都是與環境共用的 `State`；帶機率結果時，`step` 回傳各結果及其機率。每條規則以註解標出它涵蓋的訓練紀錄數與例外比例。這個模組本身就是抽取的成果，可以直接閱讀、執行與修改；它不得引用環境真正的轉移程式碼，這在程式碼層級強制，見 [architecture.md](architecture.md)。

`step` 的結構不預設：「先代理、後環境」與「先環境、後代理」兩種組合方式都嘗試，以描述長度選擇。

## 兩類規則

- **環境規則**：從「什麼都不做」的轉移中抽取。在這些轉移中代理不施加任何效果，所有變化都來自環境。
- **動作規則**：固定環境規則後，對每個動作搜尋代理階段的修改，使組合後的結果重現實際的轉移。

分開抽取，是為了讓 [attribution.md](attribution.md) 中的規則歸因估計可以成立：用同一個函式分別模擬實際動作與「什麼都不做」，兩者的差就是代理自身的影響。

## 搜尋方法

不使用大型語言模型。候選方法：

1. **列舉合取條件。** 對每個（動作，效果種類），列舉最多 k 個命題的合取。這與物件導向馬可夫決策過程的條件效果學習相同（Diuk、Cohen 與 Littman，2008）。
2. **決策樹。** 對每個（動作，狀態變數的變化）以命題為特徵訓練深度有限的決策樹，把每個葉節點轉成一條規則。
3. **歸納邏輯程式設計**，例如 Popper（Cropper 與 Morel，2021）。只在前兩種無法表達涉及隱藏變數的規則時才使用。

搜尋方法產生候選規則，選擇由描述長度決定。在第三階段開始前，以[上限對照](#上限對照)比較候選方法：在真實狀態上，哪一種能找回環境規則表中最多規則的結構、執行時間多長。選定的方法與 k 值寫進第三階段的門檻鎖定紀錄。

## 描述長度

規則集的描述長度為兩部分之和（Rissanen，1978；Grünwald，2007）：

- **規則集本身的位元數**：以固定的編碼表示規則語言中的每個元素：動作、命題的種類與值、效果的種類與參數、例外比例與機率的數值。
- **在規則集之下編碼資料的位元數**：每一筆轉移中，真實下一步在規則集之下的負對數機率。帶例外的確定性規則，以它的例外比例轉為機率；帶機率結果的規則直接使用它的機率。

兩者之和在 `val` 分割上最小的規則集被選中；相同時選較短的規則集。讀取錯誤造成的少量例外，只要規則仍能大幅壓縮資料，規則就會被保留，因此不需要另設容忍門檻。

編碼方式在門檻鎖定時寫定，之後不得更改。

## 保真度與複雜度

對一系列的複雜度上限，各自選出描述長度最短的規則集，回報它的複雜度與保真度，畫成曲線：

- **複雜度**：規則集本身的位元數。
- **保真度**：確定性環境中，下一步 `State` 完全正確的比例；帶雜訊的環境中，真實下一步的平均對數機率。

[environment.md](environment.md) 的真實規則以同一種語言編碼，在圖上標為參考點。曲線分別以讀出的狀態、真實狀態（上限對照）計算。這條曲線回答「用多少規則能解釋多少世界」，而不只是「規則是否完全正確」。

## 判定

**結構是否找回。** 對 [environment.md](environment.md) 規則表中的每一條規則（A1 至 A11、E1 至 E5）：在保留資料的真實狀態上、該規則適用的所有轉移中，選出的函式都輸出正確的結果，才算這條規則的結構被找回。帶雜訊的環境中，條件與可能結果的集合必須完全正確，機率另以與真實機率的差距回報。這裡不接受「大致吻合」：這是量測結構是否完全正確的那一端。

兩個函式只要在所有保留資料上的輸出相同就視為相同，不比較程式碼的文字。

**保真度。** 在保留資料上，函式套用到真實狀態一次、套用到讀出狀態一次；兩者的差距就是讀取誤差造成的損失。帶雜訊的環境另回報超額對數損失：函式的平均負對數機率減去真實規則的平均負對數機率，後者是任何模型都無法低於的下限。

**無法解釋的轉移。** 函式預測錯誤的轉移，以比例回報，並依它涉及的真實規則分類，不得省略。

## 回報的內容

- 每條真實規則的結構是否被找回，以及以哪一種特徵表達。
- 保真度：套用到真實狀態與讀出狀態各一次。
- 保真度–複雜度曲線與真實規則的參考點。
- 各讀取目標的準確率。
- 選出的函式：規則數、每條規則的命題數、每條規則的例外比例。

## 上限對照

把相同的搜尋與選擇流程直接套用在真實狀態上，不經過表示空間。這個結果代表搜尋方法本身能做到的上限。實際結果與上限之間的差距，就是經過表示空間所造成的損失，用來判斷失敗出在表示空間還是出在搜尋方法。

上限對照只需要環境與資料，在第零階段的環境驗收後即可進行，與第一階段並行。

## 規則開關的比較

在 `full` 與 `full-nocool` 兩套資料上分別抽取。理想的結果是：兩個函式的差別恰好是冷卻相關的規則（A8、E3、E4，以及 A5 中的冷卻條件與效果），其餘完全相同。

## 機制組合

機制組合條件中，規則從三個訓練變體合併的資料中抽取，缺席的變數依上文的方式處理。抽出的函式不經任何重新擬合，直接套用到測試變體：能量與冷卻同時限制推動的 `boxes-energy-cooldown`、箱子與球互相阻擋的 `boxes-balls`，以及全部機制的 `full`。
