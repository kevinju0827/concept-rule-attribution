# 0003. 世界模型以 LeWorldModel 為起點

- 狀態：提議中
- 日期：2026-10-02

## 背景

本專案需要一個在表示空間中預測下一步的世界模型，條件是：能在單張 8 GB 顯示記憶體的 GPU 上訓練；能防止表示崩塌，也就是避免模型把所有輸入壓成幾乎相同的表示；動作以數值輸入，讓「什麼都不做」可以作為一個明確的值。

候選：

- Dreamer 系列。強化學習中成熟的世界模型，表示是機率分布，可以直接用 KL 散度衡量兩個預測的差異。缺點是同時要重建畫面，公開的大型設定無法放進 8 GB 顯示記憶體。
- V-JEPA 2。只在表示空間預測，已展示機器人規劃能力，但模型規模大、訓練流程複雜。
- LeWorldModel。只在表示空間預測，訓練目標只有兩項：下一步表示的預測誤差，以及一個強迫表示保持分散的約束。作者報告約 1500 萬參數、單張 GPU 數小時即可訓練，並以讀取實驗顯示表示空間編碼了有意義的物理量，也能偵測物理上不可能的事件。官方程式碼位於 lucas-maes/le-wm。

2026-10-02 閱讀官方程式碼（2026-05-22 的提交 8edfeb3）確認的事實：

- 授權為 MIT。
- 編碼器為小型 Vision Transformer，方塊邊長 14 像素，預設輸入 224×224；取分類標記的輸出，經一個含批次正規化的多層感知器投影成 192 維。
- 預測器為因果遮罩的 Transformer，6 層，位置編碼為可學習的參數，長度等於歷史長度，預設 3 張畫面；動作經一個小型嵌入網路後，以調制的方式進入每一層。
- 損失為下一步表示的均方誤差，加上權重 0.09 的等向高斯約束。預設以 bf16 精度、每批 128 個樣本訓練。
- 資料欄位包括畫面、動作與本體感覺。說明文件寫的是 HDF5 格式；設定檔中 TwoRoom、Reacher、Cube 使用 HDF5，PushT 在該提交中改為 Lance 格式。
- 訓練結束後以狀態字典加設定檔的形式存檔；評估時以相對於 `$STABLEWM_HOME/checkpoints/` 的路徑或 Hugging Face 上的模型名稱載入（stable-worldmodel 0.1.1）。
- 安裝說明以 uv 建立 Python 3.10 的環境，並依賴 stable-worldmodel 與 stable-pretraining。

## 決策

提議以 LeWorldModel 為起點，在第零階段重現其公開環境的結果後，再接上客製的 MiniGrid 環境。

## 影響

LeWorldModel 的表示是單一向量而非機率分布，KL 散度無法直接用來衡量兩個預測的差異，需要另選差異量，並另寫決策紀錄。

接上本專案時必須修改預測器，修改後的版本已經不是被重現的設定：

- 動作必須從預測器的每一層移出，改由一個只接收歷史條件表示與當前動作的轉移頭處理，使歷史條件表示不含當前動作。
- 位置編碼的長度必須涵蓋整個回合，而不是 3 張畫面。每個樣本要編碼的畫面數因此大幅增加。
- 若畫面的每格像素數與方塊邊長一致，例如每格 14 像素、8×8 格子的 112×112 畫面，每個方塊恰好對應一格。

Python 3.10 於 2026 年 10 月結束支援。若官方程式碼只能在 3.10 上執行，第零階段的重現可以在獨立的 3.10 環境中進行，但本專案自己的程式碼不以已結束支援的版本為目標。

接受前須先確認：

- 授權條款允許本專案的用途。已確認為 MIT。
- 程式碼能在單張 8 GB 顯示記憶體的 GPU 上執行，重現一個公開環境的結果。
- 依上述方式修改後，以本專案的回合長度與畫面大小訓練時，最高顯示記憶體用量在 8 GB 以內，且訓練仍然穩定。
- 能在仍受支援的 Python 版本上執行，或能把需要的模組移植過來。
