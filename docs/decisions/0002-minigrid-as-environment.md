# 0002. 以 MiniGrid 作為環境

- 狀態：已接受
- 日期：2026-10-02

## 背景

本專案需要一個環境，滿足兩個條件：隨時能取得完整的真實狀態，才能檢查表示空間是否形成概念、抽出的規則是否正確；以及規則少而清楚，失敗時才知道是哪一層出了問題。

考慮過四種選擇：

- 自行從頭撰寫格子世界。規則與狀態完全自訂，但畫面繪製、物體系統等底層都要自己寫與除錯。
- MiniGrid，由 Farama Foundation 維護的格子世界套件。可直接安裝，內建完整視野、RGB 畫面與符號化觀測等轉換工具，並提供自建環境的官方教學。缺點是視覺簡單，屬於玩具環境。
- Crafter，一個 2D 的類 Minecraft 環境，有採集、合成、生存等機制，執行很快。規則較多，第一步就使用會增加診斷難度。已有研究重新實作了提供結構化狀態的物件導向版本。
- Minecraft。規則豐富、接近真實，但第一人稱畫面看不到完整狀態；取得精確的真實狀態需要額外開發；同時運作的規則太多；需要的資料量與算力高出好幾個量級。作為參考，有研究在 Minecraft 上使用了 2541 小時的遊戲錄影，以數百顆 TPU 晶片訓練。

## 決策

以 MiniGrid 作為本專案的環境，在其上以官方方式自建環境，加入本專案需要的規則與隱藏變數。

放大順序為：先在 MiniGrid 完成全部階段，再以 Crafter 檢驗結果在規則較多的環境中是否仍成立，之後才考慮規則未知或 3D 的環境。

## 影響

MiniGrid 預設把狀態完整畫在畫面上，沒有看不見的變數。隱藏變數與只透過間接線索呈現的效果，必須在客製環境中自行加入。

MiniGrid 中的 `done` 動作在基礎類別中不改變狀態，但部分內建環境把它用來結束回合，或把動作空間限制為三種。客製環境必須自行確保存在嚴格意義的「什麼都不做」動作，並在每次修改後重新確認。

環境可以完整複製，因此反事實的標準答案，包括「本來會發生但被阻止的事件」，可以直接計算，不需要額外的紀錄機制。這是 Minecraft 中最昂貴、而在這裡幾乎免費的部分。

結論的說服力受限於環境的簡單程度，必須靠後續在 Crafter 及更複雜環境上的驗證來補足。
