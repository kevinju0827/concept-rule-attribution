# 0009. 讀取目標改為逐格與相對代理的形式，對照改為基準表示與描述長度

- 狀態：已接受
- 日期：2026-10-02

## 背景

第一階段以線性讀取器檢查表示空間是否記錄了真實狀態。原本的對照方法是：每個讀取器旁，以打亂後的標籤訓練一個相同的讀取器，兩者準確率的差距稱為選擇性差距；準確率高但差距小，代表讀取器強到什麼都能擬合。

這個對照在保留資料上量不到它想量的東西。打亂後的標籤與輸入毫無關係，以它訓練的讀取器，在保留資料上必然只有隨機猜測的準確率，與表示和讀取器的能力都無關，差距因此等於「準確率減去隨機猜測」。選擇性這個概念原本來自 Hewitt 與 Liang（2019）：對照標籤是輸入的某種身分的固定隨機函數，讀取器可以靠記住對應關係拿到分數，差距才反映讀取器的記憶能力。這個做法也不能直接搬來：本專案的逐格讀取器每一格各有權重，任何逐格的固定重新標記都能被完美學會。

另外三個問題：

- **可見變數本來就能從像素直接讀出。** 在畫面完整、顏色固定的格子世界中，每一格放了什麼，以線性方式從原始像素就讀得出來。這類變數讀取成功，幾乎不能說明學出的表示形成了概念。相對地，「代理前方那一格是什麼」需要結合代理的位置、朝向與各格內容，是乘積關係，無法以線性方式從像素讀出；學出的表示若能線性讀出它，才代表模型自己算出了這個量。
- **以物體為單位的讀取目標有順序問題。** 「第一個箱子的位置」在箱子數量改變時沒有定義，也無法推廣到更多物體。逐格的目標沒有這個問題。
- **準確率會飽和。** 兩個表示都接近滿分時，準確率分不出差異。Voita 與 Titov（2020）提出以最小描述長度衡量讀取：讀取器學會標籤需要多少資料，能區分準確率相同的表示。

Othello 棋局的研究也提供了一個教訓：以絕對顏色為目標的線性讀取失敗，但以「目前玩家的棋子與對手的棋子」為目標時，線性讀取成功（Nanda、Lee 與 Wattenberg，2023）。讀取目標的參考框架選錯，會把存在的概念誤判為不存在。

## 決策

**讀取目標。**

- 逐格：每個內部格子的內容種類、顏色、受擊提示。
- 代理姿態：位置與朝向。
- 相對代理：前方一格的內容、前方第二格的內容。
- 自身的隱藏變數：能量、推動冷卻。
- 他者的隱藏變數：每個有箱子的格子中，該箱子的耐久度。
- 動態變數：每個有球的格子中，該球的行進方向。

**對照。**

- 相同架構、未經訓練的模型：必須勝過的基準。
- 原始像素上的線性讀取：參考值，說明這個變數是否本來就能從輸入以線性方式讀出。學出的表示在可見變數上不如像素，是壓縮的正常結果，不算失敗。
- 打亂標籤：只作為流程檢查，結果必須接近隨機猜測，否則代表流程中有資料洩漏。

**指標。** 準確率、各類別平均的 F1，以及線上編碼的描述長度。

**隱藏變數只在可識別的時間點上評分。** 環境記錄每個隱藏變數此刻的值是否已由歷史唯一決定，評分只使用已決定的時間點。隱藏變數的比較基準另加「單張畫面上限」：以真實的可見狀態預測該變數所能達到的最佳準確率。

不再使用「選擇性差距」這個名詞。

## 影響

讀取目標從少數幾個物體變數，增加為數十個逐格目標與數個相對、隱藏、動態目標，比較次數隨之增加，多重比較須依統計規定處理。

可見變數的讀取結果仍然回報，但只作為健全性檢查；第一階段關於概念的主要主張，落在相對代理、隱藏、動態三類變數上。

逐格目標要求畫面大小固定，這限制了推廣測試能改變的東西，例如不能測試更大的格子。
