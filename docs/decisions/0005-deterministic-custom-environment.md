# 0005. 客製環境採用確定性動態、五個動作，且每個隱藏變數都必須可由歷史識別

- 狀態：被 0016 取代
- 日期：2026-10-02

## 背景

本專案在 MiniGrid 上自建環境，原本只列出六項必要要素：環境自身的動態、屬於其他物體的隱藏變數、屬於代理自身的隱藏變數、條件式規則、可切換的看不見的時間規則、預防事件。具體形式沒有決定，無法依此撰寫程式碼。

閱讀 MiniGrid 3.1.0 原始碼後，發現幾件會讓原本的假設不成立的事：

1. **內建的移動障礙物不適合計算反事實。** `DynamicObstaclesEnv` 在代理動作之前移動障礙物，而且以拒絕取樣決定新位置：反覆抽亂數，直到抽到沒有物體、也不是代理所在的格子。因此同一步內，代理的動作不可能影響障礙物，「代理擋住路徑」這類預防事件在一步之內不可能發生；而從下一步開始，兩個分支中代理的位置不同，拒絕取樣抽亂數的次數也不同，障礙物的去向會因為亂數錯開而不同，這個差異來自實作方式，不是因果機制。以 `copy.deepcopy` 複製環境，只保證相同動作得到相同結果，不保證不同動作之間的差異都有意義。
2. **隨機的環境動態使「精確重現」無法成立。** 規則的接受標準是精確重現每一筆紀錄。障礙物若隨機移動，沒有任何確定性規則能精確重現，接受標準必須改成分布層次的檢定，失敗時更難判斷出錯的是哪一層。
3. **預設的 RGB 畫面帶有視野陰影。** `RGBImgObsWrapper` 以環境的 `highlight` 設定繪圖，預設為開啟，會把代理前方的視野範圍畫成較亮的灰色。許多格子的外觀因此隨代理的位置與朝向改變，轉身這種只改變代理朝向的動作，會讓大片畫面跟著變。
4. **格子圖片以物體的編碼為快取鍵。** 若同一種物體有不同外觀，但編碼相同，快取會回傳舊的圖片。
5. **完整動作空間中的撿起與放下沒有用途。** 本環境沒有可撿起的物體，這兩個動作在任何狀態下都等同「什麼都不做」，只會稀釋資料，並讓「什麼都不做」不再是唯一的無效果動作。
6. **隱藏變數若沒有可見的後果，任何只看畫面的學習者都無從發現它；若它的值無法由觀測歷史決定，讀取器的準確率上限就低於百分之百。** 兩種情況下，讀取失敗都無法判讀是模型沒學到，還是根本學不到。

## 決策

環境中的物體與規則：

- **箱子**：代理向前走進箱子時推動它，箱子與代理各前進一格。只有在箱子後方的格子完全空著、代理有能量、且不在推動冷卻中時才成功。箱子有隱藏的耐久度，初始值固定；代理對前方箱子使用「作用」動作時，耐久度減一，下一張畫面中箱子以實心外觀短暫提示被擊中；耐久度歸零時箱子消失。
- **巡邏球**：每一步沿著自己的行進方向前進一格；前方被擋時反轉方向並留在原地。行進方向不畫在畫面上，但可從連續兩張畫面推得。球的移動完全確定，取代內建的隨機障礙物。
- **充電格**：只有代理能站上去；代理在步末位於充電格上時，能量回到上限。
- **代理的隱藏變數**：能量，推動與作用成功時各消耗一；推動冷卻，推動成功後的固定步數內再推無效。推動冷卻就是可切換的時間規則，關閉時冷卻永遠為零，其餘一切不變。

每一步依序處理：代理的動作、巡邏球、計時器、充電。代理先動，所以代理走進球原本要進入的格子時，球在同一步內就被擋下，預防事件可以在一步之內發生。

狀態轉移完全確定，亂數只在回合開始時用來產生初始狀態。日後若加入隨機動態，每一步必須以固定的方式抽出固定數量的亂數，與動作和狀態無關，讓不同分支共用相同的外在雜訊。

動作空間為五個：左轉、右轉、前進、作用、什麼都不做。不包含撿起與放下。

每個隱藏變數都必須有可見的後果，而且它在每一步的值都能由回合開始以來的畫面與動作歷史算出。環境為每個隱藏變數記錄兩件事：此刻的值是否已由歷史唯一決定，以及決定它的事件距今幾步。

繪圖時關閉視野陰影。隱藏變數不得影響畫面中的任何像素；同一物體的不同外觀必須反映在它的編碼中。

## 影響

確定性的動態比真實世界單純。本專案因此不檢驗雜訊下的歸因與規則抽取，這留到加入隨機動態的變體，屆時須遵守上述的雜訊規定，並另訂分布層次的接受標準。

隱藏變數的初始值固定，所以它們由「回合開始以來的完整歷史」決定。這要求世界模型能看到整個回合的歷史，回合長度因此受世界模型可處理的歷史長度限制。

能量只限制推動與作用，不限制行走，避免代理在能量用完後永遠困在原地。

動作空間與 MiniGrid 內建環境不同，無法直接沿用內建環境的動作編號；本專案的環境本來就是自建的，這個代價很小。

規則中的數值，例如能量上限、冷卻步數、耐久度、回合長度、物體數量，在資料覆蓋率的試驗前只是起始值。
