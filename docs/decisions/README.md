# 決策紀錄

記錄為什麼這樣選、放棄了什麼，以及每個選擇的代價。

## 什麼該寫成紀錄

當一個選擇在結果中看不出來時就寫：形塑了某份規格的限制、刻意不採用的預設做法、代價落在選擇之外的取捨。

規格已經直接寫明的選擇，不另寫紀錄。如果「為什麼是這樣」的答案完全包含在規格中，規格就足夠了。

## 慣例

檔名為 `NNNN-簡短英文標題.md`，依建立順序編號。編號只是識別碼，不代表優先順序。

**紀錄自成一體。** 自行重述需要的背景，不連結到規格。規格會隨設計改變而被改寫，較早的紀錄若連到規格，日後會指向一份已經不是當初假設內容的文件。讀者需要的一切都在檔案內。

**紀錄接受後不再修改。** 決策被推翻或調整時，寫一筆新紀錄，並把舊紀錄的狀態改為 `被 NNNN 取代`。原本的理由保持可讀，因為決策後來被推翻的原因，通常不會出現在取代它的決策裡。

## 狀態

| 狀態 | 意義 |
| --- | --- |
| `提議中` | 已寫明理由與代價，等待決定 |
| `已接受` | 生效中，規格反映它 |
| `被 NNNN 取代` | 已不生效，保留原文 |

提議中的紀錄是論證，不是承諾。在狀態改變前，規格不應依賴它。

## 格式

```
# NNNN. 標題

- 狀態：
- 日期：

## 背景
是什麼情況讓這件事成為需要決定的問題。

## 決策
選了什麼，寫到別人能據此行動的程度。

## 影響
代價是什麼、排除了什麼，以及要讓這個決策成立，接下來必須滿足哪些條件。
```
