# 0010. 確認性分析至少五組種子，門檻以決策紀錄與 git 標籤鎖定

- 狀態：已接受
- 日期：2026-10-02

## 背景

原本的評估規定：每個設定至少三組亂數種子；各階段的通過門檻在基準線量測後才設定；通過條件事先寫定，看到結果後才選出的條件不算數。

這些規定有四個缺口：

- **沒有證明門檻先於結果的機制。** 「事先寫定」只是承諾，事後無法讓別人確認門檻確實在看到結果之前就固定了。
- **設定門檻用的資料與檢驗用的資料沒有分開。** 若用同一批模型先量基準線、設門檻，再宣稱通過，門檻等於是看著結果訂的。
- **沒有規定不確定性怎麼估計。** 同一回合內相鄰的步驟高度相關，若把每一步當成獨立樣本，信賴區間會窄得不真實。
- **三組種子太少。** 強化學習文獻一再指出，少量種子的比較常常無法重現，並建議回報區間估計而非單一數值（Henderson 等，2018；Colas、Sigaud 與 Oudeyer，2018；Agarwal 等，2021）。

## 決策

**試驗與確認分開。** 每個階段先以試驗用的種子與試驗用的資料分割量測基準線，據此設定門檻。試驗用的種子與資料不再用於確認性的結果。

**種子數。** 每個確認性的設定至少五組訓練種子。試驗顯示變異較大時，以事先寫定的最小效果量、八成的檢定力估計所需的種子數，取兩者中較大者。

**分析單位。**

- 比較不同設定時，以每個種子的結果為一個樣本，依種子編號配對，以 t 分布計算配對差的 95% 信賴區間。
- 單一模型之內的指標，以回合為單位做群集自助法，估計信賴區間。

**多重比較。** 同一階段中的確認性假設為一族，以 Holm–Bonferroni 校正。

**門檻鎖定。** 每個階段的門檻寫成一筆新的決策紀錄，內容包括指標、門檻值、門檻的依據、種子數與分析程式碼的版本。這筆紀錄提交後，在該提交上建立附註標籤，再開始任何確認性的執行。所有確認性的結果都註明所依據的標籤。看到結果後若要修改門檻，必須寫新的紀錄，修改後的結果標為探索性。

**未事先列出的分析一律標為探索性。** 探索性結果照常回報，但不作為通過與否的依據。

## 影響

每個設定的訓練次數從三次增加到至少七次（兩次試驗、五次確認）。在單張 8 GB 顯示記憶體的 GPU 上，這會拉長時程，為了結論的可信度而接受。

只有五組種子時，小的效果偵測不到。本專案的主張限於大的效果，結果中照實說明檢定力的限制。

決策紀錄接受後不再修改，這個性質正好可以用來鎖定門檻；git 標籤則讓任何人都能確認門檻提交的時間早於確認性的執行。
