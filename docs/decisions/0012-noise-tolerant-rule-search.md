# 0012. 規則搜尋容忍讀取誤差，規則是否正確以真實狀態判定

- 狀態：已接受
- 日期：2026-10-02

## 背景

規則抽取的流程是：以線性讀取器把表示讀成明確的狀態，在讀出的狀態序列上搜尋規則，以紀錄回放驗證。原本的接受標準是：一條規則只有在能精確重現它涵蓋的每一筆紀錄時才被接受，不接受「大致吻合」。

這兩件事放在一起會出問題。讀取器的準確率不會是百分之百；資料有數百萬步，一條正確的規則所涵蓋的紀錄中，只要有一筆讀錯，它就會被拒絕。結果將是幾乎沒有規則被接受，而失敗會被記在規則抽取的帳上，實際上出錯的是讀取。

「規則本身對不對」與「讀取準不準」是兩個問題，必須分開回答。

## 決策

**搜尋時容忍讀取誤差。** 在讀出的狀態上搜尋時，候選規則只要能重現它所涵蓋的訓練紀錄中至少比例 q 的部分，就保留下來。q 依試驗中量得的讀取準確率設定，並在門檻鎖定時一併寫定。

**正確與否以真實狀態判定。** 在保留資料上，把抽出的狀態轉移函式套用到環境提供的真實狀態，一條規則只有在精確重現它涵蓋的每一筆真實轉移時，才算正確。這裡不接受「大致吻合」。

**端到端的結果另外回報。** 把同一個函式套用到讀出的狀態，量測能精確重現的比例。它與上一項的差距，就是讀取誤差造成的損失。

**上限對照不容忍誤差。** 在真實狀態上搜尋時，q 為 1。

**程式結構不預設。** 狀態轉移函式可以是「先處理代理的動作，再處理環境」或「先處理環境，再處理代理的動作」，以訓練資料上的重現程度選擇。

規則的正確性以行為判定：兩個函式只要在所有保留資料上的輸出相同，就視為相同，不比較程式碼的文字。

## 影響

搜尋過程不接觸任何真實狀態，真實狀態只用於事後的判定，因此不會把標準答案洩漏給搜尋。

q 是一個可調的數值，設得太低會接受錯誤的規則，太高會拒絕正確的規則。錯誤的規則會在真實狀態的判定中被找出，所以 q 偏低的代價是可見的；偏高的代價則表現為規則覆蓋不足，同樣會在報告中顯示。

真實狀態上的判定依賴環境內部的狀態，在不能取得真實狀態的環境中無法這樣做。這是本專案選擇規則已知的格子世界的理由之一。
